# CRM 仪表盘与线索页优化 PRD

## 1. 背景

当前系统已有以下核心模块：

- `仪表盘`：位于 `/dashboard`，当前主要展示总线索数、转化率、本月销售额、风险线索、销售漏斗、最近成交。
- `我的线索`：位于 `/leads`，当前以阶段看板 + 卡片方式展示线索，点击卡片后打开右侧详情抽屉，可记录跟进、推进阶段、关闭线索、编辑基础信息。
- `数据分析`：位于 `/reports`，当前偏历史报表，包含销售漏斗、来源分布、渠道转化、ROI、业务人员排行等。

根据业务反馈，目前线索页卡片形式不够直观，总经理希望在工作台中看到每个业务人员的每日线索录入、建联行动、每日拜访客户等过程数据。结合当前系统，优化方向不是新增一堆图表，而是重新明确三个页面的职责：

- 仪表盘：用于不同岗位快速判断今天该关注什么。
- 线索页：用于高效查找、处理、跟进单条线索。
- 数据分析：用于阶段性复盘、渠道分析、业绩分析。

## 2. 产品目标

### 2.1 管理效率目标

- 业务总经理打开系统后，可以在 1 分钟内判断团队当天业务动作是否正常。
- 销售主管可以快速发现人员异常、线索停滞、逾期未跟进。
- 管理者不需要逐条翻线索，就能知道谁今天没有录入、没有建联、没有拜访。

### 2.2 工作效率目标

- 业务人员可以用表格快速筛选、排序、定位线索。
- 点击线索行后保留当前右侧详情抽屉，减少页面跳转。
- 在详情抽屉中完成记录建联、记录拜访、记录跟进、推进阶段等核心动作。

### 2.3 数据沉淀目标

- 将“线索录入、建联、拜访、跟进、转商机/成交”转化为可统计的过程数据。
- 为角色化仪表盘、日报、绩效复盘提供稳定数据口径。

## 3. 页面定位

| 页面 | 当前定位 | 优化后定位 | 主要用户 |
| --- | --- | --- | --- |
| 仪表盘 | 销售概览 | 角色化工作台，展示今日过程、异常和重点事项 | 业务员、主管、总经理 |
| 我的线索 | 阶段看板 | 表格化线索处理台，支持筛选、排序、详情抽屉 | 业务员、主管 |
| 数据分析 | 历史报表 | 周期性复盘和经营分析 | 主管、总经理 |
| 公海池 | 公共线索池 | 保持现有定位 | 有公海权限人员 |

## 4. 角色化仪表盘需求

### 4.1 业务员视角

业务员仪表盘重点不是看全局，而是帮助自己完成今天的工作。

#### 核心模块

- 今日待处理
  - 今日待跟进线索
  - 逾期未跟进线索
  - 新分配给我的线索
  - 今日需拜访客户
- 我的今日动作
  - 今日新增线索
  - 今日建联行动
  - 今日拜访客户
  - 今日跟进记录
- 我的重点线索
  - 高等级线索
  - 长时间未推进线索
  - 即将到下次跟进时间的线索

#### 页面目的

让业务员知道今天先做什么，减少漏跟进、漏拜访、漏记录。

### 4.2 销售主管视角

主管仪表盘重点是看小团队的过程执行。

#### 核心模块

- 团队今日概览
  - 今日新增线索
  - 今日建联行动
  - 今日拜访客户
  - 今日跟进次数
  - 今日转商机/成交
  - 当前逾期未跟进
- 成员每日动作表
  - 业务人员
  - 今日新增线索
  - 建联行动
  - 拜访客户
  - 跟进次数
  - 有效线索
  - 转商机/成交
  - 逾期未跟进
- 需要关注
  - 今日无新增线索人员
  - 今日无建联人员
  - 今日无拜访人员
  - 高等级线索逾期未跟进
  - 长时间停留同一阶段的线索

#### 页面目的

让主管知道今天要盯谁、盯哪条线索、盯哪个环节。

### 4.3 业务总经理视角

总经理仪表盘重点是看全公司或多团队经营健康度。

#### 核心模块

- 经营过程总览
  - 今日新增线索
  - 今日建联行动
  - 今日拜访客户
  - 今日有效线索
  - 今日转商机/成交
  - 当前风险线索
- 团队/人员过程明细
  - 支持按团队筛选
  - 支持按人员排序
  - 支持点击人员查看当天动作明细
- 过程漏斗
  - 新增线索
  - 已建联
  - 已拜访
  - 跟进中
  - 已转商机/成交
- 趋势对比
  - 最近 7 天线索录入趋势
  - 最近 7 天建联趋势
  - 最近 7 天拜访趋势
- 异常提醒
  - 今日无动作人员
  - 高等级线索超时未跟进
  - 公海池待分配过多
  - 某团队关键动作低于目标

#### 页面目的

让总经理快速判断业务健康度，知道资源、人员、过程哪里需要调整。

## 5. 线索页优化需求

### 5.1 当前问题

当前 `/leads` 使用阶段看板展示，适合表达流程阶段，但存在以下问题：

- 卡片信息密度低，不便于快速比较。
- 大量线索时横向滚动和阶段内翻页成本高。
- 管理者想看负责人、来源、最近跟进、下次跟进、风险状态时不够直观。
- 业务人员想快速筛选某类线索时，表格效率更高。

### 5.2 优化方向

将线索页主视图从“阶段看板卡片”调整为“表格列表”，保留右侧详情抽屉。看板可以作为可选视图保留，但默认视图建议改为表格。

### 5.3 表格字段

| 字段 | 说明 |
| --- | --- |
| 客户/企业 | 主识别字段，展示公司名或网址 |
| 联系人 | 客户联系人 |
| 联系方式 | 电话/微信，按权限脱敏 |
| 阶段 | L1、L2、L3、L4、成交等 |
| 状态 | 在谈、成交、丢单、公海等 |
| 来源 | 一级来源、二级来源 |
| 业务类型 | 当前已有关联业务类型 |
| 级别 | S/A/B/C |
| 负责人 | 当前 owner |
| 最近跟进 | last_contact_at |
| 下次跟进 | next_contact_at |
| 风险 | 正常、需跟进、风险 |
| 创建时间 | created_at |
| 操作 | 查看、记录跟进、推进阶段 |

### 5.4 筛选与排序

保留当前已有筛选能力，并以表格场景重新组织：

- 搜索：公司名、联系人、电话、微信、网址。
- 快捷筛选：负责人、阶段、时间。
- 高级筛选：来源、级别、标签、业务类型、风险状态、下次跟进时间。
- 排序：最近更新、最近跟进、下次跟进、创建时间、线索级别、风险优先。

### 5.5 详情抽屉

沿用当前 Sheet 详情结构，但强化动作入口：

- 顶部固定展示客户名称、阶段、负责人、风险状态。
- 基础信息区支持编辑。
- 过程动作区提供三个明确按钮：
  - 记录建联
  - 记录拜访
  - 记录跟进
- 时间线展示所有 `lead_notes` 和系统流转记录。
- 底部保留推进阶段、标记成交/丢单等操作。

## 6. 数据口径

### 6.1 今日新增线索

统计 `leads.created_at` 在今日范围内，且创建人或负责人属于当前统计范围的线索数量。

### 6.2 建联行动

统计 `lead_notes.note_type` 属于 `call`、`wechat` 的记录数量。

建议后续新增更清晰的动作类型：

- `contact_call`
- `contact_wechat`
- `contact_other`

短期可复用当前 `call`、`wechat`。

### 6.3 拜访客户

统计 `lead_notes.note_type = visit` 的记录数量。

### 6.4 跟进次数

统计所有有效 `lead_notes`，排除删除记录和纯系统记录。

### 6.5 逾期未跟进

优先根据 `next_contact_at < now()` 且线索仍为 open 判断。

如果没有下次跟进时间，则使用当前业务规则中的 warning/danger hours，以 `last_contact_at` 或 `created_at` 判断。

### 6.6 有效线索

短期可用以下口径之一：

- 阶段进入 L2 及以上。
- 或级别为 S/A/B。
- 或新增显式字段 `is_qualified`。

建议中长期新增显式有效状态，避免不同报表口径不一致。

## 7. 技术落点

### 7.1 当前可复用能力

- `components/lead-kanban.tsx`
  - 已有线索加载、筛选、风险判断、详情抽屉、记录跟进、推进阶段。
  - 可在该组件内增加表格视图，或拆分为 `LeadTable` + `LeadDetailSheet`。
- `components/dashboard.tsx`
  - 当前仪表盘入口。
  - 可升级为角色化仪表盘容器，根据 `leadScopeType` 和权限展示不同布局。
- `components/analytics-dashboard.tsx`
  - 已有团队排行和 lead_notes 统计逻辑。
  - 可复用成员、线索、跟进记录聚合方式，抽成服务方法。
- `lib/services/dashboard.ts`
  - 当前只有概览汇总和漏斗统计。
  - 建议新增 `fetchRoleDashboardSummary`、`fetchDailySalesActivity`。

### 7.2 建议新增服务方法

- `fetchDailySalesActivity(params)`
  - 入参：dateRange、teamId、ownerId、scope。
  - 出参：按人员聚合的新增线索、建联、拜访、跟进、成交、逾期。
- `fetchDashboardAlerts(params)`
  - 出参：无动作人员、高等级逾期线索、公海待分配、长期停滞线索。

### 7.3 权限规则

- `leadScopeType = self`：只展示个人仪表盘。
- `leadScopeType = team`：展示团队主管仪表盘。
- `leadScopeType = org/custom` 且 `canViewReports = true`：展示总经理仪表盘。
- 敏感联系方式继续遵守现有字段权限。

- 线索页默认改为表格视图。
- 保留点击行打开右侧详情抽屉。
- 仪表盘新增角色化布局。
- 总经理/主管视角增加“业务人员每日动作表”。
- 指标覆盖：今日新增线索、建联行动、拜访客户、跟进次数、逾期未跟进。

### P1

- 仪表盘增加趋势图：最近 7 天线索、建联、拜访。
- 增加过程漏斗：新增线索、已建联、已拜访、跟进中、成交。

- 增加异常提醒模块。

### P2

- 目标值配置和达成率。

## 9. 验收标准

- 业务员进入仪表盘能看到今日待办、逾期、个人动作数据。
- 主管进入仪表盘能看到团队成员每日动作表。
- 总经理进入仪表盘能按团队/人员查看每日过程数据。
- 线索页默认表格展示，支持搜索、筛选、排序。
- 点击表格行能打开原有详情抽屉，并完成跟进、建联、拜访、推进阶段。
- 数据口径在页面说明或内部文档中明确，避免“同一指标不同页面数字不一致”。
